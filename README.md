# HOKEMI

VIVANTに着想を得た、1人用のブラウザ・ミニゲーム集です。タイトル画面の「はじめる」からプレイできます。PC・スマホ対応。サーバー、アカウント、APIキーは不要です。

## HTMLファイルを直接開いて遊ぶ

`npm run build` は、通常の公開用ファイルに加えて **`dist/play.html`** も生成します。このファイルにはゲームのコード・スタイル・地図をすべて同梱しており、ダウンロードしてChromeやEdgeなどのブラウザで直接開けます。ゲーム本体にサーバー起動やインターネット接続は不要です。チャット内のファイルプレビューで表示エラーが出る場合も、ファイルを保存してブラウザで開いてください。

`dist/index.html` は通常のWeb公開用です。ファイルを直接開くときは `play.html` を使ってください。

## GitHub Pagesでスマホに公開する

`docs/index.html` にコード・地図・スタイルを含む公開用ゲームを置いています。音源ファイルは含みません。

1. GitHubのリポジトリ設定で **Settings → Pages** を開きます。
2. **Source: Deploy from a branch** を選びます。
3. **Branch: main**、フォルダ **/docs** を選び、**Save** します。
4. デプロイが完了すると、Pages画面に表示されるURLをスマホのSafariやChromeで開いて遊べます。

ゲームを修正したときは、`npm run build:pages` で `docs/` を更新し、ソースコードと一緒にコミット・pushしてください。Pages有効化後は、`main` の `docs/` 更新で公開版が更新されます。リポジトリの公開範囲や契約によりPagesの利用条件が異なります。

## 開発

Node.js 24 と npm を使用します（この環境では Node.js 24.19.0 で確認）。

```bash
cd /workspace/hokemiii
npm ci
npm run dev -- --port 5173
```

```bash
npm run build  # 型検査、本番用ビルド、ブラウザで直接開けるdist/play.htmlを生成
npm run build:pages  # GitHub Pages向けのdocs/も更新
npm test       # Chromiumで実際の操作、9種類の連続クリア、加速、失敗、記録保存を検証
npm run preview -- --port 4173  # 本番用ビルドを確認
```

テストは `/usr/bin/chromium` を使います。他の環境では `CHROMIUM_PATH` で実行ファイルのパスを指定してください。ブラウザが未導入なら、Playwright公式手順でChromiumを導入してから指定してください。

## ルール

- 「鳴らせ」を含む全9種類が毎周ランダムな順番で1回ずつ出現します。周回の境目でも同じゲームは連続しません。
- **1ミスでプレイ終了**。時間切れも終了です。「もう一度、潜入する」から即リスタートできます。終了時の見出しは40クリアまでは「任務失敗」、41クリア以上では「殉職」と表示します。クリア数ではゲームは止まらず、ミスするまでステージが続きます。
- 失敗後の結果画面では、問題の正解や間違いの場所を表示しません。
- 9クリアで1周。2周目1.2倍、3周目1.4倍、4周目1.6倍と加速し、最大2.4倍です。動きや制限時間、記憶時間、相手のノックも速くなります。
- スコアはクリアしたステージ数。自己最高記録はブラウザの `localStorage` に保存します。同じ端末・ブラウザで維持されます。ストレージが使えない場合もプレイ可能です。
- 自己最高が10クリア以上になると「11からはじめる」を解放します。タイトル・終了画面から選べ、11ステージ（2周目・1.2倍速、10クリア済み）から再開できます。以降のリトライも11からになり、「1からはじめる」で最初からの挑戦にも戻れます。過去の記録でも解放され、同じ端末・ブラウザに保存されます。
- 失敗画面は「あなたは〇〇です」と表示します。称号はクリア数に応じて、0〜10：KEKKAN、11〜20：SENPAN、21〜30：IPPAN、31以上：BEPPANです。「殉職」の画面でも称号を表示します。
- 「記録を共有する」は端末の共有機能、またはクリップボードを使用します。使用できない場合はコピー用テキストを表示します。オンラインランキングはありません。
- 一時停止ボタンまたは P / Esc で停止・再開。別タブへの移動時も自動停止します。
- プレー中はゲーム画面と操作ボタンを一画面に固定し、スクロールを防ぎます。動画の表示領域は設けず、ステージ画面の大きさを優先します。暗記からノックへの切り替えや4択ボタンの出現でも表示位置を維持します。

- BGM・SEのない無音のゲームです。音源データや音の再生・生成処理は含みません。

| 任務 | 操作・内容 |
| --- | --- |
| 刺せ | 横から飛ぶバナナにナイフを1回だけ投げる。バナナの移動速度は従来の約1.4倍で、周回時にはさらに加速する。画面タップ / 投げる / Space。 |
| 見つけろ | 日本地図のみ出題。四国・滋賀県・佐渡島・沖縄のいずれかが消える異変を探す。沖縄も地理的な位置と共通の縮尺で左下に収まるよう、日本列島全体を表示。開始時から間違いがある地図を直接タップして答える。選択肢・候補マーカー・記憶時間は設けない。タップ判定は図形より広めに取り、海岸付近のタップも受け付ける。大学キャンパスの問題は出題しない。 |
| 伝えろ | 紙の見出しは「認証コード」のみ。5桁の番号を3秒間記憶し、約1秒で紙が砂状に消えてからノックを開始。ノック中は数字を表示せず、自分→相手（自動）→自分→相手（自動）→自分の順で伝える。各桁は最初2〜5回、周回とともに増えて最大9回までの1桁。2回目の出題（2周目）からは40%の確率で、相手の応答のどちらか1回にフェイントが入る。例えば4回なら3回叩いたあとに間を空けて最後の1回を叩き、合計回数は変わらない。この間も相手のターンなので、こちらが叩くと即失敗。ノックの制限時間は初期16秒で、暗記・消失の時間を別に確保し、周回時には全体が加速する。入力済み回数の表示はなく、自分で数える。照合に成功すると扉が開く。多く叩くか、相手のターン中に叩くと即失敗。画面タップ / ノック / Space。 |
| 避けろ | 4列の縦レーザーは左右に移動して回避。下段を横切るレーザーはジャンプで避ける。全周回で予告を0.3秒延長し、攻撃の合間に0.6秒の休止を確保。ジャンプの滞空時間も0.45秒延ばし、予告が出てすぐのジャンプでも避けられるようにする。2周目後半に縦・横の同時発射が登場し、3周目以降は同時発射が増える。安全な列へ移動しながらジャンプする。画面の左右 / 左右ボタン / ←→で移動し、画面中央 / ジャンプボタン / ↑・Spaceでジャンプ。周回とともに予告が速くなり、縦レーザーは2列同時になる。 |
| 狙え | 動く人物の心臓の横にある白い照準へ、中央下から真上に弾を1発飛ばす。タップ位置や矢印キーでは弾道は変わらない。飛んでいる間も人物が動くので、通過するタイミングを読んで画面タップ / 撃つ / Space。人物・心臓・照準は一緒に動き、周回とともに速くなる。心臓への命中は失敗。 |
| 覚えろ | 奥行きのある階段の記録写真を記憶し、時計の時刻・人数・整備士の道具について4択で回答。道具はスパナ・ハンマー・水平器・ノコギリからランダムに変わり、形で見分けられるように描画。色の見分けを必要とする問題は出題しない。整備士は作業帽と道具が目印。写真はオリジナルイラスト。 |
| 撒け | 繁華街を3列で走り、人混みを回避する。左右タップ / 左右ボタン / ←→。逃げ切ると「任務完了」。 |
| 食べろ | 黄色い和服の大男がチャーハン10人前を食べる。画面タップ / 食べる / Spaceを10回。回数やカウントアップは表示せず、皿の残りが減っていく。2回目のクリア（2周目）から、成功時に1人前のチャーハンが皿ごと回転しながら右から左へ飛ぶ。3回目以降も同じ成功演出。長押しによる自動入力は無効。 |
| 鳴らせ | ほかの8種類と同じくランダムに出現。コードが並ぶパソコンの音楽フォルダに17ファイル名を出題ごとにランダムな順番で表示。BEPPAN.mp3だけが成功で、それ以外の16ファイル名は失敗。BEPPAN.mp8やDAKKAN.mp8も含め、名前と拡張子を見分ける。ファイル名だけの演出で、どれを選んでも音は出ません。スマホでは一覧内をスクロール、PCはクリックまたはTabとEnter / Spaceで開く。 |

## 構成

- `src/main.ts`：画面遷移、ランダム出題、周回、記録、一時停止、共有。
- `src/games.ts`：9種類のゲーム、描画、入力・成功判定。
- `src/draw.ts`：Canvasの描画。
- `src/style.css`：PC・スマホの表示。
- `src/data/japan.json`：同梱の簡略化した地図。実行時の外部取得はありません。
- `tests/game.spec.ts`：Playwrightの機能テスト。

作品の画像・俳優の肖像は使用していません。音源ファイルは同梱していません。地図の出典は [THIRD_PARTY.md](THIRD_PARTY.md) を参照してください。

`dist/` は一般の静的ホスティング、`docs/` はGitHub Pagesのブランチ公開に使用できます。初回のPages有効化はGitHubの設定画面で行います。
